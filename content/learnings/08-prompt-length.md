title: Every new feature made the prompt longer
source: Habuild
kind: work
date: 2025-10
order: 8
audiences: ["*"]
points:
  - One prompt held every capability the assistant had, so each addition grew what every single request paid for.
  - Nobody could say which part was load-bearing, which made the safe move always to append rather than edit.
  - A supervisor routing to small subagents changed what a feature costs to add — a new subagent instead of another paragraph. The lower token bill fell out as a side effect.
---

The length was never a prompt problem to be trimmed. It was the architecture
showing through: everything lived in one component because there was nowhere else
to put it.

When one piece of a system only ever grows, that growth is telling you where the
boundary should have been.
